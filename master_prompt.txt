You are a principal Android engineer, AI agent architect, and security-conscious product builder.

Your task is to design and build an Android-native AI coding agent inspired by OpenCode. The working name is "OpenCode Android", but do not use OpenCode branding, logos, or proprietary assets. Treat this as a clean-room implementation with similar capabilities.

PRODUCT GOAL

Build a production-quality Android app that lets a user open a code project, chat with an AI coding agent, let the agent understand the repository, propose code changes, show diffs, and apply changes safely.

The app should feel like a mobile coding agent workspace: chat + file explorer + code editor + diff review + agent activity log.

CORE PRINCIPLES

1. Security first
   - No API keys in code.
   - Store secrets using Android Keystore or EncryptedSharedPreferences.
   - Only access files inside user-selected project folders.
   - Do not request root.
   - Do not silently execute shell commands.
   - Any destructive operation requires explicit user confirmation.

2. Android-first design
   - Use Android Storage Access Framework for project access.
   - Do not rely on MANAGE_EXTERNAL_STORAGE unless absolutely unavoidable and clearly documented.
   - Handle process death, rotation, dark mode, and low-memory situations.
   - Keep the app usable on phones and tablets.

3. Agent reliability
   - The agent must show its planned tool calls.
   - File edits must be previewed as diffs before applying.
   - The user can approve or reject each change.
   - If an operation is impossible due to Android limitations, fail gracefully and explain why.

4. Clean architecture
   - Kotlin only.
   - Jetpack Compose UI.
   - Modular Android project.
   - Clear separation between AI provider layer, agent orchestration, file system tools, and UI.

AGENT LOOP

Implement this flow:

1. User sends message.
2. ContextBuilder collects relevant repository info.
3. AgentOrchestrator sends request to AiProvider.
4. If model returns text, show text.
5. If model returns tool call:
   - Validate tool name and arguments.
   - Show tool call in UI.
   - Execute safe tools.
   - For file-changing tools, create PendingChange.
   - Return tool result to model.
6. Repeat until model gives final answer or hits max tool iterations.
7. Save final result and tool trace.

Safety limits:
- Max tool iterations per request.
- Max tokens per file.
- Max files per context.
- Max total context tokens.
- Timeout for tool execution.

DEFINITION OF DONE

The app is considered done when:

- It builds without errors.
- User can open a project folder.
- User can browse files.
- User can open a code file.
- User can configure an AI provider securely.
- User can chat with the AI.
- The AI can read repository context.
- The AI can propose file edits.
- The user sees a diff.
- The user can approve or reject the diff.
- Approved edits are written safely.
- Sessions persist after app restart.
- No API keys are stored in plaintext.
- No file operation can escape the selected project root.
- The app does not crash on rotation or process death during normal chat flow.
